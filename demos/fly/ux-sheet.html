UX review and design rules

Connections, 3D neurons and 3D fly. A continuing design contract; not a release-verification receipt.

The scientific scene and its readout are the default. Advanced reveals specialised tools, never the meaning.

Feedback: Jason values the 3D views but reports overload, hidden science and weak cohesion. Diagnosis: after fixing co-visibility, we exposed almost every related control and confused availability with priority. This is a heuristic review informed by that feedback, not a measured usability study. The intended task is to inspect a visual and understand its evidence before varying specialised settings.

Before adding anything

  • Keep the graph, skeleton or body scene and its scientific readout visible with Advanced closed.
  • Keep separate-archive, prescribed-input, uncalibrated-movement and active comparison/drive warnings visible.
  • Collapse visibility only: preserve settings, selection, camera and replay state. Summarise hidden active settings and provide a clear reset route.
  • Use one discoverable Advanced control per view. Keep ordinary viewing and playback accessible.

Project surface budget

Use one task heading, a short context statement and concise interpretation limits. Prioritise primary controls, then aligned scientific panes, then reference detail.

At 1366 × 900, scene and raster must be co-visible. At 390 × 844, the main visual starts in the first viewport; signals follow playback before secondary material. Use one page scroll.

Essential HTML text stays at least 12px. Do not compensate for density with 9px captions. Source-renderer canvas labels retain their own rendering.

These are acceptance rules for this project, not universal UX laws. Revisit them when observation contradicts the proposed hierarchy.

Audit and implementation guardrails

The body previously gave scene annotations, raster, event stepping, activity badges and contact metrics equal prominence. Anatomy repeated its neuron picker and placed experimental controls above static shapes. Selection explanations mixed role, limitations and audit metadata. The remedy is prioritisation, not removing scientific access.

  • Scope secondary visibility on stable ancestors: network.js regenerates inspector children, and morphology.js mounts anatomy lazily. New selections and late mounts must respect the current mode.
  • Use a button with accurate aria-expanded and an explicit controlled region. Enter and Space toggle it. When collapsing, move focus out of hidden content; keep visible focus and labels.
  • Maintain one anatomy picker. Clearly distinguish static reconstructed geometry from controls affecting saved output.
  • Compare pinned before/after hashes for geometry, saved events, the native renderer and motor/contact policies. Preserve frozen research downloads and provenance bytes. Presentation changes must not silently revise science.
Release checks and review record

Check fresh loads, every view, keyboard use, long labels, loading/error states and both target widths. Change gain/seed, select another neuron, open lazy anatomy, toggle during replay and collapse with comparison or drive blocks active. Verify retained values, truthful summaries, pairing caveats, the clear action and iframe resizing.

Run affected source/browser checks and the publication build/link check. Inspect screenshots and compare scientific-file hashes. Automated tests reduce regression risk; they do not establish comprehension or guarantee usability.

Proposed observer tasks — not executed

Invite a reader unfamiliar with the project to think aloud. Give these tasks without pointing to controls; record their words, actions, wrong turns and assistance. Do not invent task times or usability scores.

  1. Identify the question this view helps investigate and the observation it displays.
  2. Explain which parts are saved evidence, static source anatomy or assumed movement.
  3. Find a specialised setting through Advanced without losing the main scientific view.
  4. Change it, collapse Advanced and explain the still-active setting and resulting display.
  5. Return to defaults, then switch views and explain the remaining state.

Log unaided, assisted or unsuccessful completion with concrete evidence. If essential interpretation fails, revise the default surface before adding detail. This is a proposed five-task script, not completed user research.

Design sources and scientific boundaries
  • NN/G: Progressive Disclosure supports separating common tasks from specialised options and making the route discoverable. Choosing that split still requires task research.
  • GOV.UK: Details reserves disclosure for optional material. Therefore primary readouts and interpretation-critical warnings remain visible.
  • W3C: Disclosure pattern defines keyboard activation and expanded-state semantics. This project also requires a controlled-region reference and explicit focus checks.

Scientific boundaries remain governed by the paired-replay provenance, anatomy provenance and separate body archive. This sheet changes presentation priorities, not model claims.
